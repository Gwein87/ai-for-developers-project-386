# Приветственная страница «Календарь звонков»

Дата фиксации: 8 ноября 2026 года.
Статус: решения и границы тестирования согласованы пользователем.
Основной источник спецификации: [GitHub Issue #1](https://github.com/Gwein87/ai-for-developers-project-386/issues/1).

## Проблема

Стартовый экран показывает техническую информацию вместо описания сервиса.
Гостю нужен понятный вход в запись на звонок, а владельцу календаря — видимый
переход в раздел управления.

## Решение

Компактная приветственная страница со светлым фоном, крупным заголовком
«Календарь звонков», кратким описанием и верхней полосой навигации.
Описание: «Выберите тип встречи и удобное свободное время — сервис поможет
записаться на звонок без долгих согласований».

## Пользовательские истории

1. Как гость, я хочу видеть название сервиса, чтобы понимать, куда я попал.
2. Как гость, я хочу прочитать краткое описание сервиса, чтобы понять его пользу.
3. Как гость, я хочу видеть действие «Записаться» в верхней навигации,
   чтобы найти вход в запись на звонок.
4. Как гость, я хочу перейти по этому действию на `/booking`,
   чтобы открыть раздел записи на звонок.
5. Как владелец календаря, я хочу видеть действие «Админка» в верхней навигации,
   чтобы найти вход в раздел управления.
6. Как владелец календаря, я хочу перейти по этому действию на `/admin`,
   чтобы открыть раздел управления.
7. Как пользователь ещё не реализованного раздела, я хочу видеть сообщение
   «Раздел готовится», чтобы понимать его текущее состояние.
8. Как пользователь временной страницы, я хочу иметь ссылку на главную,
   чтобы продолжить навигацию.
9. Как гость, я хочу видеть на главной информацию о сервисе без технической
   карточки и проверки API, чтобы сосредоточиться на записи на звонок.

## Принятые решения по реализации

- Главная страница остаётся компактной: название, описание и верхняя навигация.
- Оформление спокойное: светлый фон и крупный заголовок.
- «Записаться» — визуально основное действие; «Админка» — менее акцентное.
- «Записаться» ведёт на `/booking`, «Админка» — на `/admin`.
- Пока оба раздела показывают сообщение «Раздел готовится» и ссылку на главную.
- Техническая карточка со стеком и кнопка «Проверить API» удаляются с главной.
- Используется установленный в проекте стек React, TypeScript, Vite и shadcn/ui.
- Изменения схемы данных и API для этого объёма не требуются.

## Решения по тестированию

- Первая граница тестирования — пользовательский интерфейс корневого приложения
  через React Testing Library в Vitest и jsdom, по образцу существующего
  дымового теста приложения.
- Проверяются заголовок и описание главной, адреса ссылок «Записаться»
  и «Админка», содержимое временных разделов и ссылка возврата на главную.
- Проверки опираются на видимые тексты, роли и адреса ссылок, без проверки
  внутреннего устройства компонентов и CSS-классов.
- Вторая граница — приложение в браузере: переходы с главной по обеим ссылкам,
  возврат на главную по ссылке, работа кнопки браузера «Назад», прямое открытие
  и обновление `/booking` и `/admin`.
- Браузерная проверка дополняет проверки компонентов реальной навигацией.
  Локальная проверка не подтверждает настройку production-сервера;
  автоматическое сравнение внешнего вида не входит в эти проверки.
- Общая проверка качества проекта — `npm run check`.

## Вне объёма

- Выбор типа встречи, поиск свободных интервалов и подтверждение записи на звонок.
- Управление типами встреч и просмотр предстоящих встреч.
- Авторизация и разграничение доступа к админке.
- Изменения базы данных и миграции.

## Дополнительные замечания

- Содержание и оформление согласованы пользователем в этом чате.
- Реализация уже находится в рабочем дереве; эта спецификация фиксирует
  договорённости после написания кода.
- Общая проверка качества прошла до создания спецификации.
- TDD при написании текущей реализации не соблюдался; согласование тестовой
  границы сейчас не означает, что цикл red → green был выполнен ранее.
- Итоговое ревью и коммит ещё не выполнены.
- Браузерная проверка переходов ещё не выполнена.
- Спецификация публикуется в GitHub Issues с меткой `ready-for-agent`
  согласно настройкам трекера проекта.
