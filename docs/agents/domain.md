# Документация предметной области

Правила использования документации предметной области инженерными навыками.

## Перед изучением кодовой базы

Прочитай, если они существуют:

- `GLOSSARY.md` в корне репозитория;
- относящиеся к задаче ADR из `docs/adr/`.

Если файла или каталога нет, продолжай работу без предупреждения и не предлагай
создать его заранее. Навык `domain-modeling` создаёт такие документы по мере
появления подтверждённых терминов и решений.

## Структура файлов

Репозиторий использует структуру single-context:

```text
/
├── GLOSSARY.md
├── docs/
│   └── adr/
└── src/
```

## Термины глоссария

При именовании предметных понятий в задачах, предложениях по рефакторингу,
гипотезах и тестах используй термины из `GLOSSARY.md`. Не заменяй их
синонимами, которые глоссарий исключает.

Если нужного понятия нет, проверь, действительно ли проекту нужен новый термин.
Подтверждённый пробел зафиксируй с помощью навыка `domain-modeling`.

## Конфликты с ADR

Если предлагаемое изменение противоречит существующему ADR, укажи конфликт
явно и объясни, почему решение стоит пересмотреть.
