# Правила проекта

## Язык артефактов

- Веди текстовые артефакты для людей, включая `AGENTS.md` и документацию, на
  русском языке.
- Веди инфраструктурные артефакты, включая конфигурацию, workflow и скрипты, на
  английском языке. На английском также сохраняй код, идентификаторы, имена
  инструментов и сообщения коммитов. Правила коммитов описаны в
  `CONTRIBUTING.md`.

## Структура репозитория

- Размещай рабочий код в `src`, а тесты — в `tests`.
- Называй каждый проект `HexletCalendar.*`. Включай в `HexletCalendar.slnx`
  только проекты бэкенда; frontend-проекты и frontend-тесты в solution не
  добавляй.

## Бэкенд

- Используй .NET 10 и ASP.NET Core.
- Используй SQLite для хранения данных. Создавай и применяй миграции EF Core
  только через CLI `dotnet ef`.
- Перед созданием каждой миграции остановись и получи явное разрешение
  пользователя. Не создавай миграцию попутно с другим изменением.
- Управляй созданием базы явно: приложение не должно автоматически создавать
  или мигрировать базу при запуске.

## Фронтенд

- Используй React, TypeScript, Vite и shadcn/ui. Храни переиспользуемые
  компоненты shadcn в `src/HexletCalendar.Web/src/components/ui`.
- Работай с npm из корня репозитория. При изменении зависимостей запускай
  `npm install`, добавляй полученный `package-lock.json` в коммит и считай этот
  файл генерируемым. Не добавляй артефакты других пакетных менеджеров.

## Тесты и проверки качества

- Для тестов бэкенда используй xUnit с `Microsoft.AspNetCore.Mvc.Testing`, а для
  фронтенда — Vitest с React Testing Library и jsdom.
- При изменении поведения добавляй или обновляй тесты. Дымовые тесты приложений
  должны запускаться общей командой тестирования репозитория.
- Перед завершением любого изменения кода или конфигурации запусти
  `npm run check` из корня репозитория и устрани все ошибки. Эту же проверку
  GitHub Actions выполняет при каждом push.
- Сохраняй в корневой цепочке проверок ESLint, анализаторы и форматирование
  .NET SDK, Knip, Commitlint, тесты фронтенда и бэкенда и production-сборку
  фронтенда. Сохраняй jactionlint и OSV-Scanner включёнными в GitHub Actions.
- Добавляй исключение из проверок качества только после решения человека.
  Делай исключение минимальным и фиксируй причину и дату пересмотра.
- Сохраняй `.github/workflows/hexlet-check.yml` без изменений: этот файл
  генерирует Hexlet.

## Коммиты

- Следуй типам, областям, языку и формату Conventional Commits из
  `CONTRIBUTING.md`.

## Навыки агентов

### Обязательный флоу Мэтта

Перед началом задачи и при возобновлении работы в новом чате прочитай
`docs/agents/matt-flow.md` и следуй указанной там спецификации флоу.

### Трекер задач

Задачи и спецификации хранятся в GitHub Issues. Подробнее см.
`docs/agents/issue-tracker.md`.

### Метки triage

Используются стандартные метки triage. Подробнее см.
`docs/agents/triage-labels.md`.

### Документация предметной области

Используется структура single-context: корневой `GLOSSARY.md` и ADR в
`docs/adr/`. Подробнее см. `docs/agents/domain.md`.
